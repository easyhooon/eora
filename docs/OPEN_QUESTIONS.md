## 레퍼런스(QAKit 영상)와 설계 문서가 충돌하는 항목

영상에서 확인한 흐름: shake → 메뉴(피드백 보내기 / 로그 분석 / 개발자 모드) → 화면에 표시 → 리포터/담당자 → 상세 입력(유형, QA 피드백/일반 피드백, QA 태스크, 제목 등) → 전송. 메뉴·편집기·상세 입력 필드는 레퍼런스에 맞췄고, 아래 항목은 답을 받은 뒤 구현합니다.

15. ~~새 이슈를 생성하나요, 기존 이슈에 첨부하나요?~~ **결정(2026-10-20): 새 이슈 생성.** `IssueUploader.createIssue` → 파일별 `upload` 순서입니다. 제목은 필수이고, 본문은 메타데이터 + 상세 입력입니다. 생성 응답이 유실되면 다시 만들지 않고 사용자 확인을 받습니다.
16. **리포터·담당자: Jira REST 조사 결과.** acli에는 사용자 목록 명령이 없습니다(로컬 `acli 1.3.39` help 확인). Jira Cloud REST `GET /rest/api/3/user/assignable/search?project=KEY&query=…`(담당자 후보), `GET /rest/api/3/user/search` 를 게이트웨이가 호출하는 방식을 권장합니다. 호출 계정에는 "Browse users and groups" 권한이 필요하고, 사용자는 `accountId`로 식별합니다. 이메일은 프로필 설정에 따라 빠질 수 있습니다. 서비스 계정으로 이슈를 만들면서 리포터를 지정하려면 "Modify Reporter" 권한이 필요합니다. REST 세부 내용은 문서 페이지가 잘려 공식 문서로 다시 확인해야 합니다. **남은 결정**: 리포터를 로그인 사용자로 자동 지정할지, 목록에서 고를지.
