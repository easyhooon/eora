# Roadmap

현재는 문서 단계입니다. 아래 단계는 우선순위 제안이며 완료된 기능이나 일정 약속이 아닙니다.

## Phase 0 — 작은 문제 검증

- QA 담당자가 최근 티켓 하나를 작성하는 흐름을 확인합니다.
- 캡처→표시→첨부 과정에서 실제 반복되는 불편 한 가지를 고릅니다.
- 첫 호스트 앱, STG 변형, Android 최소 버전과 검증 기기를 정합니다.
- 실제 사용자·운영 데이터 없이 재현 가능한 샘플 화면을 준비합니다.
- 개인정보 취급 범위와 파일 보관 기한·크기 한도를 결정합니다.

통과 기준: 누가 언제 쓰는지, 기존 흐름에서 무엇을 줄일지 설명할 수 있습니다. 반복 수요가 없다면 범용 SDK를 먼저 만들지 않습니다.

## Phase 1 — 개발 검증용 로컬 캡처 PoC

범위:

- STG foreground shake-to-open과 수동 호출 대체 경로
- 제보 UI가 나타나기 전 캡처, 단일 제보 흐름·감도·쿨다운 제어
- 원·화살표·텍스트, 실행 취소, 불투명 가림
- 허용된 기기·버전·화면 메타데이터
- 최종 미리보기와 로컬 초안·삭제

개발자가 익숙한 앱 하나에서 1–3일짜리 탐색으로 시작할 수 있는 범위입니다. 호환성 대응과 안정화까지의 완료 보장은 아닙니다. 서버나 실제 Jira 업로드는 포함하지 않습니다. 이 단계는 개발자 검증용이며 QA 사용자에게 제공할 MVP가 아닙니다. 파일 이동·CLI 업로드를 QA 사용자에게 요구하는 흐름으로 대체하지 않습니다.

통과 기준: QA 사용자가 샘플 문제의 위치와 재현 맥락을 한 묶음으로 만들 수 있고, 가리기 전 원본이 산출물에 섞이지 않습니다.

## Phase 2 — 사용자용 MVP: 앱 안에서 Jira 직접 첨부

선행 결정:

- Jira Cloud 또는 Data Center
- 인증 주체, 게이트웨이 운영 주체와 프로젝트 권한
- 자체 서버/서버리스 여부, 호출자 접근 제어, 토큰 만료·교체 및 인증 실패 복구 책임
- 업로드 가능 형식·크기·임시 보관 정책

범위:

- 새 이슈 생성(제목·본문 검토)
- 승인된 최종 파일·메타데이터 첨부
- 기존 영상 선택과 미리보기
- 파일별 결과 표시, 보고서 ID 기반 중복 방지
- 부분 성공·응답 유실의 확인 및 사용자 주도 복구

통과 기준: 테스트 전용 티켓에서 정상·권한 부족·용량 초과·오프라인·부분 성공·응답 유실을 검증합니다. 반복 탭이나 재시도로 성공한 파일이 다시 첨부되지 않으며, 불확실한 상태를 성공으로 표시하지 않습니다.

## Phase 3 — 호스트별 적용과 선택적 녹화

- 호스트 앱의 메타데이터·진입 UI·업로더 교체 경계 정리
- Native View·Compose·WebView 호환성 표를 실제 결과로 작성
- 필요한 경우에만 MediaProjection 녹화 추가
- 사용자 동의, 앱 단위 녹화, 시작·중지·회전·잠금·용량 제한 검증

통과 기준: 첫 사용자가 반복 사용하며, 두 번째 호스트에 적용했을 때 복사·붙여넣기보다 명확한 이점이 있습니다. 일반화를 위해 사용하지 않는 옵션을 추가하지 않습니다.

## 병행 MVP — 작은 로컬 Developer mode

1. 호스트 프런트엔드에서 실제 storage read/write와 소비 지점을 조사합니다. 키·타입·기본값·origin·초기화 의미·새로고침 필요를 기록합니다.
2. QA에 필요한 소수의 비민감 항목을 선택하고 읽기/쓰기/초기화 콜백으로 등록합니다.
3. 현재값·기본 버튼·Boolean 토글만 구현하고 reset/unset을 구분합니다. 다른 타입은 읽기 전용 또는 호스트 버튼 콜백으로 제한하며 범용 편집기를 만들지 않습니다.
4. STG origin/키 제한, 페이지 준비·전환, 실패·재조회, release/no-op을 검증합니다.

기존 프런트엔드 저장소를 그대로 사용하며 별도 shadow flag store를 기본으로 만들지 않습니다. 전체 쿠키·캐시 삭제, 전체 로그아웃, 서버 관리자 상태 변경은 이 MVP에서 제외합니다. 앱 내 Jira 직접 첨부의 필수 범위도 유지합니다. 실제 호스트 코드와 키가 확인되기 전에는 동작을 추정해 구현하지 않습니다.

## 현재 범위 밖의 선택지

서버 QA 액션은 새로운 요청과 별도 검토·승인 전에는 구현하지 않습니다. 향후 검토 조건으로는 승인 API, 테스트 계정 제한, 서버 권한 확인과 확인·감사 절차가 있습니다. 승인된 기존 봇 서버의 Jira 업로더 재사용도 선택 사항입니다. 없는 봇 플랫폼을 먼저 구축하거나 QA 사용자에게 메신저 수동 작업을 추가하지 않습니다.

## Phase 4 — 공개 배포 판단

- API와 패키지명, 샘플 앱, 지원 버전 문서 확정
- release/no-op 누출 검사와 테스트 자동화
- 라이선스, 배포 채널, 버전 정책 결정
- 알려진 제한과 데이터 처리 문서 공개

이 단계 전까지 Maven 좌표·설치 명령·지원 버전 보장을 발표하지 않습니다. 공개 저장소 생성과 SDK 배포는 별도입니다.

## 필수 테스트 목록

### 로컬·단위 테스트

- 메타데이터 허용 목록, 민감 URL·토큰 제외
- 좌표 변환·가림 합성·원본 제외
- shake 감지·쿨다운·중복 이벤트 및 lifecycle 전환 시 상태 초기화
- 초안 TTL·용량 제한과 삭제
- 보고서 revision 변경 시 승인 무효화
- 부분 성공 상태 전이와 반복 전송 방지

### 기기·통합 테스트

- View·Compose·WebView, 별도 Window·Surface 포함 화면
- 가로/세로 회전, 키보드, 앱 백그라운드, 프로세스 종료
- 센서 없음·흔들기 어려운 환경의 수동 경로, 연속 흔들기·오탐
- 비동기 캡처 중 화면 전환, 제보 UI가 캡처에 섞이지 않는지 확인
- Dari desktop-only와 동시 사용, 다른 디버그 도구의 shake 충돌
- 캡처 불가·저장공간 부족·파일 선택 취소
- 녹화 도입 시 동의 거절·시스템 중지·화면 잠금
- Jira 접근/첨부 권한, 파일 제한, 연결 끊김, 응답 유실
- 검토 화면과 실제 업로드 파일의 일치
- release 산출물에 QA 권한·서비스·UI·업로더가 없는지 검사

문서 단계이므로 위 테스트는 아직 실행하지 않았습니다.

## 현재 제외 범위

자동 버그 판단, 상시 화면 녹화, 몰래 실행되는 캡처, 전체 로그·네트워크 본문 수집, 자동 개인정보 검출 보장, 사용자 승인 없는 티켓 생성·기존 티켓 수정, 기존 첨부 교체·삭제, 자동 백그라운드 업로드, AI 분석 서버는 초기 범위에서 제외합니다.

## 성공 판단

기능 수보다 실제 티켓 작성 시간과 개발자의 재질문 횟수를 관찰합니다. 개인별 행동 추적을 새로 만들기보다 소수의 샘플 작업에서 전후 과정을 비교합니다. 반복 사용이 없거나 유지 부담이 편익보다 커지면 확장을 멈추고 로컬 도구로 남깁니다.
