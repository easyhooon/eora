# Features

이 문서의 모든 기능은 계획입니다. 체크리스트는 구현 완료 표시가 아니라 향후 검증 기준입니다.

## 1. STG 전용 shake-to-open

- 기본 진입은 기기를 흔들어 여는 방식입니다. 상시 플로팅 버튼·오버레이로 제품 화면을 가리지 않습니다.
- 호스트 앱이 foreground이고 캡처할 활성 화면이 있을 때만 감지합니다. pause/stop 시 센서 구독을 해제하고 재개 시 이전 흔들림 상태를 초기화합니다.
- 감도·감지 구간·쿨다운을 조정할 수 있게 설계합니다. 중복 이벤트를 합치고 캡처·제보 흐름은 한 번에 하나만 실행합니다.
- 흔들림 감지 시 **제보 UI를 열기 전에 원래 앱 화면을 캡처**합니다. 캡처가 끝나기 전에 화면이 바뀌거나 background로 이동하면 결과를 폐기/취소하고 다시 시도하도록 안내합니다.
- 최초 사용 안내에서 흔들기가 로컬 화면 캡처를 시작한다는 점을 설명합니다. 외부 업로드와 녹화는 별도 명시 동작·동의를 요구합니다.
- 센서가 없거나 흔들기 어려운 사용자·에뮬레이터를 위해 호스트가 수동으로 호출할 경로를 제공합니다. 호출 API 이름·서명은 아직 미정입니다.
- 일반적인 가속도계 샘플링을 사용하고 불필요한 고속 센서·위치·카메라·마이크·오버레이 권한을 요구하지 않는 방향입니다.
- 실제 구현은 STG 변형에만 연결합니다. release에는 의존성을 제거하거나 동일한 호출 지점의 no-op을 제공합니다.

완료 기준: 연속 흔들기·걷기·회전의 오탐, foreground 전환, 센서 부재, 수동 호출, 제보 중 재진입을 검증합니다. release 결과물에 센서 구독·QA 화면·녹화 서비스·업로더·관련 권한이 유입되지 않아야 합니다. 단순 런타임 플래그만으로 숨기지 않습니다.

참고: Android 센서의 존재 여부는 기기별로 다르므로 런타임에서 확인합니다. [Android 센서 문서](https://developer.android.com/develop/sensors-and-location/sensors/sensors_overview)

## 2. 캡처와 주석

- 현재 앱 화면 캡처 후 이미지 편집기로 이동합니다.
- 원·화살표·텍스트 및 실행 취소를 제공합니다.
- 민감 영역은 불투명 사각형으로 가립니다. 단순 흐림 효과를 보안상 완전 삭제로 취급하지 않습니다.
- 최종 업로드 파일은 주석과 가림을 합성한 이미지입니다. 가려지기 전 원본을 함께 첨부하지 않습니다.
- 취소하면 업로드하지 않고 임시 자료를 정리합니다.

완료 기준: 화면 회전·스크롤·이미지 확대 후에도 표시 좌표가 일치하며, 미리보기와 전송 파일이 동일합니다. 보호된 화면 등 캡처 불가 상황은 우회하지 않고 안내합니다.

호환성: 일반 View, Compose, WebView를 각각 검증합니다. 팝업·별도 Window·SurfaceView·영상 표면이 같은 방식으로 잡힌다고 가정하지 않습니다. PixelCopy의 Window 복사는 API 26부터 제공되지만, 이 사실만으로 모든 UI의 호환성을 보장하지 않습니다. [PixelCopy 공식 문서](https://developer.android.com/reference/android/view/PixelCopy)

## 3. 기존 영상 첨부와 후속 녹화

MVP에서는 사용자가 이미 녹화한 영상 또는 이미지를 선택합니다. 지원되는 기기에서는 시스템 Photo Picker 등 제한된 선택 경로를 검토합니다. 전체 갤러리 접근을 기본 요구하지 않습니다. [Photo Picker](https://developer.android.com/training/data-storage/shared/photopicker)

- 선택 파일의 형식·크기·길이를 확인하고 전송 전 미리보기를 제공합니다.
- 영상 자동 개인정보 제거는 MVP에 포함하지 않습니다. 민감정보가 보이면 해당 영상을 제외하거나 외부에서 편집한 파일로 대체합니다.
- 선택한 파일만 취급하며 다른 미디어를 탐색하지 않습니다.

후속 단계에서는 MediaProjection 기반 명시적 시작·중지 녹화를 검토합니다. 매 세션 사용자 동의, foreground service, 회전, 중단, 자원 해제와 크기 제한을 함께 구현해야 합니다. Android 14+ 타깃은 mediaProjection 서비스 유형·권한 선언이 필요합니다. [MediaProjection](https://developer.android.com/media/grow/media-projection)

## 4. 재현 메타데이터

허용 목록 후보:

- 앱 버전 이름·코드와 STG 환경 표시
- Android 버전, 기기 제조사·모델
- 호스트 앱이 정의한 안전한 화면 식별자
- 사용자가 작성한 재현 단계와 기대/실제 결과
- 보고서 UUID 및 생성 시각

기본 제외: 전체 URL과 쿼리·fragment, 쿠키, 헤더, 토큰, WebView DOM, 폼 입력, 사용자 식별자, 원시 네트워크 본문·로그, 의료·건강 정보. URL 경로에도 식별자가 있을 수 있으므로 쿼리 제거만으로 안전하다고 보지 않습니다.

완료 기준: 미허용 필드는 출력에서 빠지고, 호스트의 커스텀 필드도 검토 화면에 노출됩니다. 검토 후 내용이 바뀌면 기존 승인을 재사용하지 않습니다.

## 5. 앱 안에서 새 Jira 이슈 생성과 첨부

사용자용 MVP의 필수 범위입니다. 파일 내보내기 후 수동 첨부나 CLI 사용을 QA의 대체 경로로 강제하지 않습니다. 인증·토큰 교체 방식은 결정 전이며 안전한 무로그인 사용을 보장하지 않습니다.

- 제보마다 새 이슈를 하나 만들고, 승인된 파일을 그 이슈에 첨부합니다(2026-10-20 결정, OPEN_QUESTIONS #15).
- 이슈 제목은 사용자가 입력한 제목(필수), 본문은 허용 목록 메타데이터와 상세 입력 내용입니다. 전송 전에 본문 텍스트 그대로를 보여 줍니다.
- 기존 이슈의 본문 수정·댓글 작성·상태 변경·기존 첨부 삭제는 제외합니다.
- 리포터·담당자는 게이트웨이가 Jira REST(`user/assignable/search`)로 가져오는 방안을 검토 중입니다(OPEN_QUESTIONS #16).
- Jira Cloud/Data Center 및 인증 방식 확정 후 해당 어댑터를 구현합니다.

Cloud API는 multipart 첨부 추가를 제공하며, 첨부 활성화 여부·최대 크기는 별도 설정 조회로 확인할 수 있습니다. 이슈 접근과 첨부 권한도 필요합니다. 동일 파일명은 교체 키가 아닙니다. [Jira Cloud 첨부 API](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issue-attachments/)

이슈 생성 응답이 유실되면 다시 만들지 않고 '결과 확인 필요'로 두어, 사용자가 생성 여부를 확인하게 합니다. 게이트웨이는 reportId와 revision으로 중복 생성을 막는 방안을 검토합니다.

완료 기준: 권한 부족, 입력값 거부, 크기 초과, 부분 성공, 이슈 생성·첨부 응답 유실을 구분합니다. 성공한 파일을 다시 올리지 않고 기존 첨부를 임의 삭제하지 않습니다.

## 6. 보관·실패·재시도

- 앱 전용 임시 저장소를 사용하며 공개 갤러리에 자동 저장하지 않습니다.
- TTL, 총 용량·파일 수·개별 파일 크기 상한을 구현 전에 정합니다.
- 취소·삭제·만료 시 원본과 파생 파일을 함께 정리합니다. 서버 임시 파일의 보관 정책은 별도로 둡니다.
- 업로드에 성공한 Jira 첨부는 로컬 정리와 별개로 남는다는 점을 알립니다.
- 오프라인에서는 로컬 초안으로 유지하거나 사용자가 삭제합니다. 연결 복구만으로 전송하지 않습니다.
- 재시도는 사용자 동작으로 시작하고, 대상·내용 변경 시 다시 검토합니다.

완료 기준: 앱 재시작 후 만료 자료 정리, 저장공간 부족 처리, 부분 업로드 복구, 중복 탭 방지, 전송 중 취소의 실제 상태 안내를 검증합니다. 취소가 이미 전송된 첨부의 삭제를 의미한다고 표시하지 않습니다.
